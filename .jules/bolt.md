## 2025-02-12 - Component Resource Sharing in R3F
**Learning:** Instantiating `three.js` primitives (like `ConeGeometry` and `MeshBasicMaterial`) directly inline within a component, especially inside high-frequency render loops or large arrays of meshes (like `FirePit`), causes excessive memory allocations and Garbage Collection (GC) overhead. While R3F's auto-dispose mechanism typically handles cleanup, pre-allocating these objects outside the component entirely eliminates this per-render allocation cost.
**Action:** When identifying identical primitive instances rendered en-masse (like identical flames in a fire pit), pre-allocate them outside the React component. Critically, apply `dispose={null}` to the `<mesh>` properties referencing these shared objects to prevent R3F from erroneously disposing of the shared resource when a single instance unmounts.
