## 2024-05-24 - Pre-allocating Geometries and Optimizing Loops in React Three Fiber
**Learning:** Instantiating `ConeGeometry` or `MeshBasicMaterial` inside high-frequency components or loops (like `FirePit`) causes severe memory overhead and GC pressure. Also, using `.forEach()` inside `useFrame` allocates closures every frame. Furthermore, using floating point steps in `for` loops can lead to IEEE 754 precision issues requiring an epsilon. When sharing pre-instantiated materials/geometries in R3F, they might be auto-disposed when one consumer unmounts unless `dispose={null}` is used.
**Action:** Always pre-allocate static geometries and materials outside of the component body. Use a standard `for` loop instead of `.forEach()` in `useFrame`. Use an epsilon for floating point loop bounds. Set `dispose={null}` on `<mesh>` when sharing pre-instantiated resources.
